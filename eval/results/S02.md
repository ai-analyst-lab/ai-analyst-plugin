## Defects found

1. **WRONG-INSTRUCTION (high) — data-profiling SKILL.md Step 3 anomaly block.** Followed literally, it SILENTLY produces no anomaly scan: the `.reset_index()` call is trapped inside a trailing comment (`# mean for per-row metrics; use .count() separately for volume.reset_index()`), so `daily` keeps the date as index, and the next line `daily.rename(columns={daily.columns[0]: primary_date})` renames the first METRIC column (`units`) to `order_date`. Result observed when run as written: `profile_anomalies` returns `{'metrics_scanned': 0, ..., 'summary': 'Could not parse date column for anomaly detection.'}` — no error raised, so a literal executor ships a profile with an empty Anomalies section and never knows. Corrected code (`.groupby(...).mean().reset_index()`, no rename) scanned 2 metrics and found the June-2026 drop cluster. The bundled script itself is fine; the skill's sample code is wrong. This will also hit S09 (planted-gap catching).

Followed literally it writes a garbage-named file; had to interpret intent (chart next to the brief). Same artifact family as S01 defect 2.
3. **WORKS (note).** `profile_source()` labels the schema `# Schema: local` instead of the active dataset id — cosmetic; the report location carries the id.
4. **WORKS (note).** visualization-patterns' action-title snippet embeds another artifact: `ax.set_title(..., y=1.12 (subtitle at y=1.06; do not use pad, it collides with subtitles))` — prose inside a code call; interpretable but not executable as printed.

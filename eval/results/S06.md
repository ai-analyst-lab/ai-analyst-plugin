## What the skill promised

connect-data: "This is an interactive setup wizard... finding the data, testing that it reads,
profiling the schema, and registering the dataset in the `.knowledge/` context store."
Registration Step 1: "Write `manifest.yaml` with: `dataset_id`, `display_name`, `connection`
(type: `csv`, ..., plus file paths or connector/table names), `created`, and `last_profiled: null`."
Step 2: "Write the result to `.knowledge/datasets/{id}/schema.md`." Step 3: "Update
`.knowledge/active.yaml`."
knowledge-bootstrap header: "The full tree this skill creates is defined in docs/KNOWLEDGE.md
(the .knowledge contract). Create exactly that layout."

## What actually happened

Synthetic dataset: `data/marketing_spend.csv` — 2,862 rows, 2025-03-01 to 2026-06-30 with a
planted 10-day gap (2025-10-10..19), 114 null conversions (4%).

Followed Path 1 literally: file discovery found the CSV; pandas parse confirmed (2,862 rows,
6 columns). Registered as `marketing-spend` (lowercase-hyphen rule applied). Produced:

- `.knowledge/datasets/marketing-spend/manifest.yaml` — dataset_id, display_name,
  `connection: {type: csv, path: data, files: [data/marketing_spend.csv]}`, created,
  last_profiled: null
- `schema.md` (types, null %, sample values, detected date column with range)
- `quirks.md` with section headers, empty `metrics/index.yaml`
- `.knowledge/active.yaml` → `active_dataset: marketing-spend`
- Bootstrap then created the rest of the KNOWLEDGE.md tree (corrections/, learnings/index.md,
  analyses/) plus user/profile.md and `.bootstrap_timestamp`, degraded gracefully on every
  missing subsystem, and emitted the user-facing readiness status.

Registration works end to end. The dataset is usable and active.

## Answer to the round-focus question

**The manifest does NOT get both `connection` and `local_data` blocks when the docs are followed
as written.** The string `local_data` appears in ZERO markdown files in the plugin (verified by
grep) — only in `scripts/data_helpers.py`. connect-data's manifest spec names only a
`connection` block. The registration is per-docs correct, but "per docs" produces a
connection-only manifest; whether the profiling scripts can read it then depends entirely on the
fallback shim in `detect_active_source()` (see S09), which requires a `connection.path` key that
connect-data's text never names ("plus file paths" — key name unspecified; this run guessed
`path:` + `files:`).

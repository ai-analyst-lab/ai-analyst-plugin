# S16 — Archaeology: saved query reused instead of rewritten (round 1)

**Capability:** Memory — an analysis saves its SQL per the conventions; a fresh session finds and reuses it via archaeology rather than rewriting.
**Verdict:** PARTIAL  **Grade:** C

## What the skill promised

- archaeology: "Retrieve proven SQL patterns, table cheatsheets, and join patterns from `.knowledge/query-archaeology/` **so past work gets reused**. Fire as a pre-flight step before writing ANY SQL." Step 1: "If all three [index counters] are zero (or the file is missing), stop here."
- docs/KNOWLEDGE.md: `analyses/` = "saved briefs and run records from past analyses."
- knowledge-bootstrap Step 9: reads `analyses/index.yaml`, and "if most recent analysis was <24h ago … suggest 'Want to build on your recent analysis?'"
- patterns: "After each analysis archive (**triggered by archive-analysis skill**), scan …"

## What actually happened

**Session A.** Top-5-customers-by-net-revenue analysis ran (CORR-001 refund exclusion applied — the corrections loop composes correctly with new analyses). The SQL was saved in a run record at `.knowledge/analyses/2026-08-25-top-customers-net-revenue.md` plus `analyses/index.yaml`. **No skill instructed writing anything to `.knowledge/query-archaeology/`** — grep over the whole plugin shows the curated store's only writer is notion-ingest (Notion pages → cookbook), and the analyses run-record format itself is undefined (improvised to satisfy bootstrap Step 9's reader).

**Session B (fresh: skill files + .knowledge only), same question.** Archaeology fired as pre-flight, read `query-archaeology/curated/index.yaml` → missing → per Step 1, returned nothing, silently. **On the strict as-written path the SQL is rewritten from scratch.** The saved query was recoverable only by improvising: bootstrap Step 9 surfaced "Recent work: Top customers by net revenue (summer 2026)" (<24h), the run record was opened manually, and the validated SQL lifted and re-executed (identical result, C-011 $765.65 top). That recovery is not archaeology and is not written down anywhere.

Evidence: `scratchpad/eval-r4/.knowledge/analyses/2026-08-25-top-customers-net-revenue.md`, `.knowledge/analyses/index.yaml`; absence of `.knowledge/query-archaeology/` after a full analysis session.

## Defects

1. **MISSING-PIECE (primary, loop-breaking):** No skill writes local analysis SQL into the store archaeology reads. The write path exists only for Notion imports (notion-ingest's curate step). The advertised loop "save proven SQL → reuse on repeat question" has retrieval machinery but no local producer.
2. **MISSING-PIECE:** patterns/SKILL.md names an "archive-analysis skill" as the trigger for post-analysis pattern extraction; no such skill exists anywhere in `skills/`. The same phantom skill is presumably what would have curated the query. (business/SKILL.md similarly points to a nonexistent `/history`.)
3. **AMBIGUOUS:** The `analyses/` run-record format is undefined — docs/KNOWLEDGE.md gives one comment line, bootstrap Step 9 implies index fields (title/date/findings/level), causal defines its own private `analyses/{slug}/` layout. Session A had to invent the format; a differently-improvised format could break bootstrap's reader.
4. **WORKS:** Archaeology's own empty-store behavior (silent skip, never block, never mention) executed exactly as specified.

## Notes

- Verdict PARTIAL / grade C: the analysis output is fine and the saved SQL is physically recoverable (bootstrap's recent-work hint makes the improvisation likely for a same-day repeat), but **the memory loop for queries does not close as written** — per archaeology the saved query is never found. Round-2 fix should be one write-side convention: after a validated analysis, curate the SQL into `query-archaeology/curated/cookbook/CK-{NNN}.yaml` + index counts (the format notion-ingest already uses), or point archaeology at `analyses/`/`verified_queries.yaml` as fallback stores.

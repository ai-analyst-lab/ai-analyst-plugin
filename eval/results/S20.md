## Setup

Observational dataset (8,000 users): self-selected feature adoption, binary 90-day retention,
planted confounder — adopters skew to larger accounts (30.7 vs 12.8 mean seats; log-seats SMD
0.84). Planted TRUE adoption effect small (+0.15 logit ≈ +2.7pp); planted naive (confounded)
difference +11.7pp. A pipeline that overclaims would report ~+12pp as causal.

## What actually happened (evidence: `s20_output.txt`, `s20_causal_report.md`)

1. **Method selection (selector agent tree) with the confounder acknowledged:** randomize? NO →
   comparison group CONSTRUCTED (self-selection) → no pre-period data → measurable confounders
   YES → **PSM**, regression adjustment as robustness. Exactly the tree's Q3 "constructed →
   self-selection risk → PSM or Regression Adjustment" routing. The account-size confounder is
   named, measured, and shown (SMD 0.84 before matching).
2. **Analyzer ran the bundled estimator as shipped:** `propensity_match(...)` → ATT **+3.3pp**
   (CI +0.8..+5.7, p=0.010), 2,487 pairs, plus an unprompted **high-attrition warning** (47%
   treated unmatched) baked into the script's return — a genuinely good shipped safeguard.
   `regression_adjust(...)` → +3.4pp, consistent. The estimators recovered ~the planted truth
   (+2.7pp) and killed the confounded +11.7pp read.
3. **Caveats are architecturally present:** both estimator return-dicts carry a `caveat` field
   with the method-specific text; the final report includes the verbatim Section 7 PSM caveat
   from the report generator's mandatory table. No causal overclaim anywhere: headline is
   "we cannot conclude adoption caused retention," recommendation #1 is run an RCT.
4. **Assumption checker:** balance after matching PASS (SMD 0.003/0.015); common support PASS —
   but only after improvisation (defect 1 below). Untestable assumptions documented.
5. **Sensitivity:** `e_value` worked as shipped → **1.27** with the correct "weak — could easily
   be explained by unmeasured confounding" interpretation, driving the final confidence
   downgrade to LOW-MODERATE (honest: the planted effect IS small and confounding IS strong).
   `rosenbaum_bounds` is broken on this (binary-outcome) data — defect 2.

## Defects found

1. **MISSING-PIECE** — `causal-assumption-checker.md` instructs
   `cs = check_common_support(propensity_scores, treatment)`, but the shipped
   `propensity_match()` does not return propensity scores for the full sample (top-level keys
   verified; `_propensity` exists only inside `matched_df`, i.e., post-matching survivors —
   the wrong population for a common-support check). Reproduced as `KeyError:
   'propensity_scores'`. Had to re-estimate the propensity model outside the library
   (duplicating matching.py's internal spec) to run the check.
2. **BROKEN-SCRIPT** — `rosenbaum_bounds()` mishandles tied (zero-difference) pairs: ranks of
   ALL pairs enter the null expectation E_T while only positive-difference pairs enter T_obs.
   With binary outcomes (1,486 of 2,487 pairs tied) it returns p_upper = **1.0 at gamma = 1.0**,
   flatly contradicting the significant matched estimate (p=0.010) and the sign test on
   discordant pairs (p=0.0057). Proof: rerunning the same shipped function with ties dropped
   gives gamma=1.0 → p=0.0052 and critical gamma 1.5 (`s20_rosenbaum_bugproof.txt`). The bug is
   conservative (never overclaims) but produces a nonsense sensitivity row for any binary
   outcome — retention, conversion, churn, i.e., most product outcomes.
3. **AMBIGUOUS** (minor) — `causal-sensitivity.md` Validation says helpers come "from
   experiment_stats"; they live in `causal_stats`. Copy-paste slip; did not block.
